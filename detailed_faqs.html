Frequently Asked Questions & Technical Specifications

Detailed breakdown of Qbonic’s 100% in-browser memory model, Groq AI metadata isolation, GDPR/CCPA compliance, telemetry, and payment security.

🛡️ 1. Core Data Privacy & Zero-Server-Upload Architecture

100% in-browser processing. Raw CSV, TSV, and Excel data is parsed directly inside your device's local memory (RAM / Web Workers). Zero raw spreadsheet cell values or customer records are ever uploaded to remote servers or third-party cloud databases.

No. We operate on a strict Zero-Data Architecture. We have no database tables or storage buckets capable of holding your spreadsheet rows.

You can open your browser Developer Tools (F12) → Network tab while loading files and pivoting data. You will observe zero file payloads or raw cell data uploaded over the network.

No. Your browser makes a direct client-side HTTPS fetch to Google's public CSV export endpoint. Qbonic's servers never touch the connection.

All in-memory parsed rows are immediately wiped and garbage-collected by your browser's JavaScript runtime engine.

No. Qbonic runs in an isolated client-side React scope. We do not load third-party ad trackers, tag managers, or invasive session-replay scripts.

No. All aggregation sums, sparkline trends, and pivot table cells are rendered locally in your browser DOM.

🤖 2. AI Classification & Groq API Key Security

No. Groq AI only receives high-level column metadata (header names, inferred data types, distinct value counts, and up to 3 anonymized sample values) to suggest smart classifications and formulas. Your full dataset, customer tables, and financial records are never uploaded or shared with external AI servers.

Absolutely. Qbonic includes an intelligent built-in rule heuristics engine that works out of the box with zero API key or configuration required. Because spreadsheets vary across business domains, automated classifications (both rule-based and AI) serve as smart starting points—we recommend reviewing the interactive Configuration page to fine-tune column types, unit formats (Currency, %, Count), and custom KPI formulas for your exact use case.

Your Groq API key is stored exclusively in your browser's private `localStorage` (`qbonic_groq_api_key`). It is never transmitted to Qbonic servers or telemetry.

Under Groq's API terms of service, data sent via API is processed for inference and is not used to train foundational AI models.

Navigate to Settings → AI Configuration and click "Remove Key". It is instantly purged from your browser storage.

⚖️ 3. Regulatory & Legal Compliance (GDPR, CCPA, HIPAA)

Yes. Qbonic is engineered on strict "Privacy-by-Design" principles (GDPR Article 25). Because raw dataset rows never leave your computer, there is zero persistent cloud data retention and zero invasive third-party cross-site advertising cookies.

Because processing occurs entirely on the user's local hardware without uploading Protected Health Information (PHI) to cloud servers, Qbonic supports secure local healthcare data analysis.

You can request permanent account deletion by emailing `admin@qbonic.com`. All account metadata in Firestore is wiped within 30 days. No raw dataset rows exist to erase.

No. We do not use Meta Pixel, Google Ads remarketing pixels, or third-party behavioral advertising cookies.

📊 4. Product Usage Telemetry & Error Logging

We collect lightweight milestone event logs: event name (e.g. `DATASET_LOADED`, `REPORT_SAVED`), pseudonymous `User_UID`, device type, browser, screen resolution, and unhandled error stack traces.

In accordance with GDPR Article 25 (Privacy by Design), using pseudonymous business IDs (e.g., `SHP1000001` or guest session hash) prevents PII (email addresses) from proliferating into operational telemetry logs.

Strictly zero. Telemetry only captures high-level counts (e.g., row count tier `10K-30K`, total dimensions `4`). Cell values and financial amounts are never captured.

🔐 5. User Authentication & Cloud Sync

Only basic profile identity (`email`, `name`, `photoURL`). Qbonic requests zero access to your Google Drive, Gmail, or Google Contacts.

Saved report workspaces (column layouts, formulas, aliases) are stored locally in your browser's `localStorage` / `IndexedDB` for 100% privacy.

🏢 8. Enterprise Governance & Security

In the current MVP release, Qbonic focuses exclusively on real-time interactive in-browser dashboard exploration, filtering, and metric calculation. File exports (such as downloading modified CSVs or PDF reports) are not currently supported; your source files remain untouched on your device, and saved dashboard views are stored privately in your local browser storage.

We maintain a responsible disclosure program. Please report any security findings to `security@qbonic.com` or `admin@qbonic.com`.
